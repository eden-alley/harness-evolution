# 第一至四篇：循环、工具、权限与上下文管理

在[第一篇](https://namiai.tech/articles/agent-minimal-loop/)的基础上，
依次加入[第二篇](https://namiai.tech/articles/agent-tools/)、
[第三篇](https://namiai.tech/articles/agent-permissions/)与
[第四篇](https://namiai.tech/articles/agent-context/)的内容：

- `agent.py`：`Agent` 实例及模型/工具循环，运行状态不再放在模块全局。
- `cli.py`：创建客户端、本机配置、终端输入、`/auto`、`/new` 与会话加载保存。
- `prompts.py`：系统提示词与退出检查提示词。
- `tools.py`：工具注册表与 `Toolset`，显式绑定工作区和命令执行器。
- `sandbox.py`：按用户要求新增，调用本机 Codex CLI 的 Windows MXC 沙箱执行命令。
- `permissions.py`：共享的 `Workspace` 路径边界，以及风险等级、硬规则和人工确认。
- `context.py`：截断、清理、摘要和 `SessionStore`；会话格式仍是原来的 JSON 消息列表。
- `token_usage.py`：`TokenUsage` 实例统计；由 Agent 持有，不使用全局累计变量。
- `tests/test_permissions.py`：原文的六个权限测试。
- `tests/test_agent_loop.py`：四个离线场景测试，每个场景同时验收多项行为。
- `tests/test_context.py`：四个上下文与持久化综合场景。
- `tests/test_token_usage.py`：两个 token 统计综合场景。
- `tests/test_shell_encoding.py`：两个命令输出编码综合场景，使用真实本地子进程。
- `tests/test_exit_check.py`：五个退出检查综合场景，覆盖完成、继续、受阻、失败和轮数上限。
- `tests/test_new_session.py`：三个新会话综合场景，覆盖备份、上下文隔离、用量保留和写入失败。
- `tests/test_sandbox.py`：五个沙箱执行层离线场景，不需要实际启动 Codex。
- `tests/test_sandbox_native.py`：三个真实 Windows 沙箱场景，不调用真实模型。
- `tests/test_auto_permissions.py`：三个自动执行综合场景，覆盖切换、硬规则、实际工具执行和新会话。
- `tests/scenario_support.py`：本地模拟模型响应和仅供测试注入的样本命令执行器。
- `tests/test_structure.py`：导入无副作用、实例状态隔离、共享工作区和执行器注入。
- `tests/run_offline.py`：分组运行基础测试及本机沙箱验收，不依赖 pytest。

五个工具是 `list_dir`、`read_file`、`write_file`、`run_shell`、`fetch_url`。
统一执行器将工具异常返回给模型，并保留原文的前 8000 字符截断。
第四篇再在结果进入消息历史前做一次更短的头尾截断。

教程代码保留这些本机适配，并在代码中标注；后续按用户要求加入的功能单独说明：

- 读取本机已有的 `DEEPSEEK_API_KEY`；终端未继承时读取 Windows 用户环境变量。
- 默认模型改为本机密钥可用的 `deepseek-flash`，使用非思考模式匹配原文消息格式。
- 摘要请求也使用同一个模型，并关闭默认思考模式。
- 告诉模型本机使用 Windows cmd，以及当前 Python 解释器的路径。
- 命令输出按原始字节接收；标准输出和错误输出分别先尝试 UTF-8（含 BOM），失败后
  尝试 GBK，均失败时用替换符保留可读内容，避免读取线程解码异常及 `None` 输出。

命令输出优先按 UTF-8 解释；如果字节同时符合两种编码，也按这个顺序选择，并不是通用
编码检测器。同一输出流内部混用不同编码时不保证能完全还原。退出码、工作目录、超时、
权限确认及换行处理保留原有行为。

工具调用日志使用纯文本标签，替代原文的表情符号。

使用原文的 `openai` SDK，电脑上已安装。密钥不写入文件。
执行 shell 命令还依赖 PATH 中的原生 `codex.exe`，需要支持 Windows MXC 沙箱。
本机已用桌面应用附带的 `codex-cli 0.166.0-alpha.5.1` 验证；npm 的 `codex.ps1` / `codex.cmd`
不会作为执行入口。这里只调用本地 `sandbox` 子命令，不调用 Codex 模型。

## 运行

在 PowerShell 中执行：

```powershell
cd 'D:\AgentLearning\agent-minimal-loop\playground'
$env:NAMI_WORKSPACE = (Get-Location).Path
py -3 ..\agent.py
```

启动后输入任务，例如：

```text
你> 写一个 fib.py，输出斐波那契数列前 10 项，然后运行它确认结果是对的
你> exit
```

`NAMI_WORKSPACE` 指定工作区；不设置时使用启动时的当前目录。文件工具的检查和执行
共用同一个 `Workspace` 对象，禁止访问工作区外的路径。命令从工作区启动，超时为 30 秒。

## 第三篇的权限行为

- `list_dir`、`read_file`：工作区内自动放行。
- `write_file`、`run_shell`、`fetch_url`：执行前展示真实参数，输入 `y` 允许、`n` 拒绝。
- `write_file` 额外支持 `a`，本次会话内一直允许；硬规则仍然生效。
- 人工确认模式下，`run_shell` 不支持一直允许，每条命令都需要确认。
- 路径越界或命中原文危险命令规则时直接拒绝，不提供人工放行选项。
- 未登记风险的新工具默认需要确认；非交互环境无法确认时默认拒绝。
- 拒绝时可以附带原因，程序会把拒绝结果交回模型。

这部分沿用第三篇的人工确认机制。命令正则主要是原文的 Unix 风格示例，
不是完整的 Windows 命令防护。后续按用户要求接入的命令沙箱如下。

## 自动执行开关（按用户要求新增）

在 `你>` 提示符下单独输入：

```text
/auto on     开启：现有已登记工具免确认
/auto off    关闭：恢复人工确认
/auto        查看当前状态
```

程序启动时默认关闭。开启后，写文件、执行命令和抓取网页不再逐次询问；路径越界、
危险命令及被策略禁用的工具仍然拒绝，未知风险的工具仍需确认。关闭时清除本次记住的
「一直允许」，让需要确认的工具恢复询问。

开关只影响确认步骤：`run_shell` 仍通过同一个 Windows MXC 沙箱执行，失败时不会改用
宿主 shell；`fetch_url` 仍在宿主进程运行，开启后也免确认，并未因此获得沙箱隔离。
这是真实执行工具的环境，沙箱不等于模拟执行，也不保证阻止读取工作区外的所有文件。

`/new` 保留当前开关状态；重启程序后恢复关闭，状态不写入会话。上述命令及无效参数
由程序直接处理，不请求模型、不进入聊天历史、不改变 token 统计。

## Windows 原生命令沙箱（按用户要求新增）

接入沙箱时只替换 `run_shell` 的执行层；自动执行开关另按上节控制确认步骤。
`sandbox.py` 固定调用 `codex.exe sandbox`，显式选择 `windows.sandbox=mxc`、内置 `:workspace`
权限配置，并遵守机器的托管要求。不会安装软件、改动用户的全局 Codex 配置或使用 Docker。

- 命令在 Windows 原生进程隔离中执行，写权限覆盖当前工作区及配置允许的系统临时目录。
  在本机真实测试中，向工作区外的普通对照目录写入被拒绝，原文件保持不变。
- **这不是完整的宿主文件读取隔离。** 内置工作区配置允许读取部分工作区外文件，真实测试已确认
  能读取同级对照目录里的样本。私有文件的读取隔离需要后续单独设计，不能据此假定密钥文件不可见。
- 本机当前配置下，沙箱中的 Python 无法连接宿主 localhost 的测试监听端口；网络边界由 Codex
  权限配置执行。本项目的 `fetch_url` 仍在宿主进程运行，默认需要人工确认，不属于命令沙箱。
- 子进程仅继承运行所需的环境变量，API key、业务变量及代理认证变量不下发。此措施不代替文件读取隔离。
- 执行器必须是工作区外的原生 exe。命令不会先经过宿主 shell；缺少执行器、沙箱不支持或启动失败时，
  将错误返回模型，不回退为宿主机直接执行。
- Windows 引号经临时批处理脚本传递，脚本只在沙箱内运行并在结束后清理。命令遵循 cmd 批处理语法，
  `for` 变量使用 `%%i`。原有 UTF-8 / GBK 解码、退出码和 30 秒超时保留；超时及中断会清理进程树。

模型 API 请求仍由宿主 Agent 发出，因此继续使用现有 DeepSeek key。沙箱本身不产生模型 token。
本机曾试用 legacy elevated 执行器，发现它创建的文件在仅使用 OWNER RIGHTS 的目录中可能让宿主无法读取；
最终固定使用已验证可用的 MXC，不会自动降级到 legacy 执行器。

本次验收先验证执行层的参数、环境和失败行为，再运行真实沙箱中的文件、网络和子进程测试，最后运行完整回归。
真实测试仅使用专门创建的样本和临时目录，不读取用户的私有文件或发送真实模型请求。

## 会话和验证

每次提问最多运行 30 轮执行循环；摘要和退出检查会在轮内额外请求模型。
退出检查要求继续时仍消耗原来的执行轮数，不重新开始计数。
输入 `exit` 或 `quit` 退出。

第四篇增加的上下文规则：

- 工具结果进入历史前，保留头尾合计 4000 字符，另加中间省略说明。
- 上一次请求的 `prompt_tokens` 超过 16000 时，把旧工具结果替换为占位文字，保留最近 3 条。
- 超过 24000 时改为摘要压缩；系统消息和最近 2 轮用户对话原样保留。
- 清理只改 `tool.content`，摘要只在用户回合边界切分，保留工具调用与结果的配对。
- 每次提问完成后保存 `default` 会话，启动时自动加载；权限管理器重新创建，授权选择不写入会话。

默认会话文件：`C:\Users\叶宸玮\.nami-agent\sessions\default.json`。
可通过原文提供的 `NAMI_STATE_DIR` 指定状态目录；按上面的启动方式，它位于练习工作区之外。
代码不会把本次 Codex 聊天写入会话文件，只保存你在该 Agent 中输入的内容及其响应。

按用户审核后的方案新增 `/new`，不属于第四篇原文。开始另一项任务前，先单独输入
`/new`，再输入新任务；同一任务的追问直接输入，继续沿用当前会话。

- 先将当前会话备份为同目录下的 `default-backup-<随机编号>.json`，连续新建使用不同文件名。
- 将当前上下文重置为只有系统提示词，并立即保存新的 `default.json`；重启后也不恢复旧任务。
- 只将用于上下文压缩的“上次请求输入量”归零，整个进程的 token 累计保留。
- 命令由程序处理，不调用模型；输出备份文件名，不改变工作区文件和当前进程的权限选择。

升级后需重新启动程序加载新代码，再输入 `/new` 切换会话；进程重启后的 token 累计
仍沿用原来从零开始的行为，`/new` 本身不清零累计。备份只在执行该命令时创建。

摘要会额外消耗 API 余额，且有损；16000/24000 沿用原文的演示阈值。
只含一个很长用户任务时没有足够的回合边界可供摘要；依据上一轮用量处理，也不保证
当前新增内容永远不会超过模型窗口。原文的这些限制保留，没有加入额外压缩策略。
`tools.py` 已截掉的原始结果尾部也无法由后续头尾截断找回。

第四篇本次仅作离线验收，没有调用真实模型或写入默认用户会话目录。

## Token 统计（按用户要求新增）

每次请求使用 API 返回的 `prompt_tokens`、`completion_tokens` 和 `total_tokens`，显示
输入、输出、合计以及本次程序运行的累计值，并区分对话、摘要和退出检查请求。不计算价格。

```text
[对话 tokens] 输入=500 输出=20 合计=520 | 本次运行累计：输入=500 输出=20 合计=520
```

累计值只保存在内存中，重启程序后从零开始；恢复聊天记录不会恢复之前的用量。
上下文压缩仍依据最近一次对话请求的输入量，不使用累计值。缓存输入属于输入量的一部分，
不会再重复相加。缺少 usage 时明确提示未计入累计；请求失败而没有用量响应时也不猜测。

## 退出检查（按用户审核后的方案新增）

实现位于 `agent.py` 的 `Agent.check_exit(task)`，不属于教程原文。
只有执行模型没有返回工具调用、准备给出最终回答时，才使用同一个模型额外检查一次。
检查输入是原始任务、当前实际对话记录（包含工具结果）和候选回答；检查请求不提供工具。
检查器只返回 JSON：`{"decision":"completed|continue|blocked","reason":"原因"}`。

- `completed`：返回执行模型的候选回答。
- `continue`：将原因作为“继续当前任务”的反馈加入历史，继续原来的循环。
- `blocked`：返回阻碍原因，明确标注任务受阻、未完成。
- 请求失败、非法 JSON 或字段不合法：明确提示退出检查失败、任务未标记完成，并停止本次循环。
- 达到当前的 30 轮上限：沿用最大步数停止提示，检查器不能重置或延长上限。

检查响应的 usage 计入 token 累计，包括响应内容不合法但已收到 usage 的情况；
上下文清理仍依据最近一次执行请求的输入量。检查用的对话和判定不会另行加入执行历史，
仅在需要继续时加入反馈。实际运行会增加检查请求的 API 用量，本次仅作离线测试。
检查结果是模型根据现有证据作出的判断，离线测试验证流程，不代表真实模型一定判断正确。

结构整理后，导入核心模块不会读取密钥或创建客户端。工作区、消息、压缩依据和
token 累计由实例持有；基本测试不修改模块全局变量，也不需要本机 Codex。

基础组包含 37 项测试（含原文六项权限测试），使用本地模型响应和显式注入的测试执行器：

```powershell
cd 'D:\AgentLearning\agent-minimal-loop'
py -3 tests/run_offline.py
```

真实沙箱三项单独运行，继续验证越界写入、网络限制和子进程清理；不会因为失败而修改
测试标准。缺少执行器导致跳过时，此命令也返回失败，不能算作验收通过。

```powershell
py -3 tests/run_offline.py --native
```

测试执行器只存在于测试辅助文件；正式入口始终选择原生沙箱，缺失或失败不回退为普通
进程。结构整理保留了原来的权限确认、清理策略、退出检查和会话格式，没有合并 v2-refactor。
